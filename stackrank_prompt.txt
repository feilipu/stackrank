# Goal

A single-user local web app that ranks and funds **sub-projects** under one
overall project name and a budget. Three complementary decision modes:

1. Automatic optimize — exact 0/1 knapsack with precedence (ancestor-closed).
2. In-budget success pool — drag/click into a pool that never exceeds budget.
3. Elo beauty contest — pairwise A/B comparisons (K = 32) with a live board.

# Product (must match this behaviour)

## Overall project

- Editable title, default `Untitled project`, 1–80 chars after trim.
- Stored in `settings.project_name`. Rename in the sticky header.

## Sub-projects

Each sub-project has:

- name (unique, 1–80 chars)
- description (optional)
- notes (optional, max 500 chars, shown on cards and export)
- **entered cost**: `cost_amount` (the number typed) + `cost_currency`
  (`SGD` | `USD` | `MYR`)
- `cost_sgd` — derived at the current FX rates; used by knapsack, pool, Elo/S$
- outcome (positive)
- dependencies (zero or more other sub-projects; no self-edges, no cycles)
- Elo 1500, matches/wins/losses
- created_at / updated_at ISO-8601 UTC

Edit form must show the **entered** amount and currency, not a reverse
conversion from SGD. Saving unchanged values must keep those fields exactly.
Changing USD/MYR rates recomputes every `cost_sgd` from entered amount+currency
and rebalances the pool.

`settings.last_cost_currency` is the add-form default (updated on create and
edit). Fallback SGD.

## Budget and FX

- Base unit SGD. Rates are “foreign per 1 SGD” (`usd_per_sgd` default 0.74,
  `myr_per_sgd` default 3.45). No live FX API.
- Budget form: amount + currency. Persist `budget_sgd` and `budget_currency`.
- Every money display is a triple: `S$…  ·  US$…  ·  RM…`.
- Default budget S$250,000.

## Projects tab

- Add form, in-place edit, delete with confirm.
- Search `q` (name, description, notes, case-insensitive).
- Filter `pool=all|in|out`. Sort `name|cost|outcome|elo|efficiency`; `dir`.
- Efficiency: `outcome/cost_sgd` and `elo/cost_sgd` on cards.
- In-pool cards green (`sub-in`), out-of-pool amber (`sub-out`).
- SVG dependency sketch: current project on the right, deps on the left,
  dynamic box width (no truncated titles), class `dep-sketch`.
- Empty list: empty-state art + sentence.

## Optimize tab

- Metric: outcome | elo | blend.
  `blend = 0.6 * outcome + 0.4 * (elo / 15)`.
- Exact DP, costs rounded to integer SGD, n typically ≤ 30, ancestor-closed.
- Show selected, excluded, totals, remaining (3 currencies).
- Apply writes the selected set into the pool (replace pool membership).
- Last run persisted in `settings.last_optimize_json` so GET survives restart.

## Pool tab

- Available column vs In-Budget Success Pool. SortableJS + HTMX.
- Add: if the new item does not fit, eject lowest unpinned by pool metric
  (outcome | elo | blend). Pinned items never auto-eject. Missing dependencies
  are pulled in when possible; otherwise 409.
- Remove blocked if a pooled dependent still needs this project.
- Pin toggle. Reorder persists positions (0 = highest priority).
- Sticky site tabs. Under them, 50/50 sticky row: Budget+FX (left, min 18rem)
  and duck-pool fill (right). Auto-eject metric under that row.
- `#pool-fill`: HTML water, fill from the basin floor (side view). Caption
  `N% full`, bold and readable. Over-budget tints water red. Duck on the
  surface, waves clipped to water, terracotta rim even at 100%.
- Totals: in-pool count, spent, remaining (or over-by), outcome, Elo sum.

## Contest tab

- Two large cards, A better / Skip / B better. K = 32.
- Skip: no Elo/W-L change; still counted as shown.
- Pairing: unseen unordered pairs first, then closest Elo; randomize A/B.
- Progress: unique pairs decided. Stop, reset (confirm), **undo last match**
  (restore Elo and W-L from `contest_matches` before/after columns).
- Recap of last action. Leaderboard. Empty art when idle.

## Export tab

Same sticky chrome as other tabs.

- Full report: compact HTML tables, pool then excluded, one row per project.
  Print CSS ~8pt so 35–50 items fit ~2–3 pages.
- Contractor list: accepted (in-pool) only, no Budget line in the report
  body, **Total = sum of pool cost_sgd** in the selected currency, stated
  twice (header + under table).
- Currency selectable via `?ccy=SGD|USD|MYR` (toolbar GET form + links).
- Screen dark theme: pool rows dark green + light type; excluded dark amber;
  beat the injected light `_SHEET_STYLE` with `html.dark` `!important` in
  `app.css`. Print stays light.
- Markdown download for both views. Filename from slugged project name.
- Colour key: green `#ecfdf5` / `#047857` in pool, amber `#fff7ed` / `#c2410c`
  excluded (light); dark-mode greens/ambers as in `html.dark .sub-in/.sub-out`.

## Theme

- `settings.theme`: `system` | `light` | `dark`. Follow `prefers-color-scheme`
  when system. Blocking script sets `html.dark` before paint.
- Theme POST stays on the current tab (`next=` allowlisted paths).
- Selected **nav tab** uses the same chip as the selected theme button:
  `bg-indigo-600 text-white` (Tailwind Play injects after `app.css`; do not
  rely on `text-brand-dark` in dark mode).
- White Tailwind frames in dark (contest, projects, pool budget/rates/totals,
  export) need `html.dark` scoped `!important` (Play utilities otherwise win).

## Friend launch

- `./run.sh` and `./install.sh` (alias): Python 3.11+, venv, pip,
  `uvicorn` on 127.0.0.1:8000, **no `--reload`**, open default browser.
- `./scripts/pack.sh` → `dist/stackrank-YYYYMMDD.zip` without `.venv`, live
  `data/*.db`, `.git`, `handoff.md`, `implementation-summary.md`.
- First launch with empty `data/` seeds 12 example projects.
- Runtime: `requirements.txt`. Tests: `requirements-dev.txt`. pytest via
  `.venv/bin/python -m pytest`. Temp DB only; never touch live `data/stackrank.db`.
